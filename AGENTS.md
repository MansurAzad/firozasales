- Post stock issues, sales, payments and settlements only through the atomic `post_transaction` RPC; direct financial writes are revoked to prevent partial posting and history manipulation.
- Read financial balances through the RLS-preserving `accounting_snapshot` RPC for a consistent view without Data API row truncation.
- Reports and business documents derive only from `accounting_snapshot`; browser-only export libraries are dynamically loaded, and PDF/print share a branded paginated paper layout to preserve Bengali text and authorized visibility.
- SR activation changes use the admin-authorized `set_sr_active` RPC; self-service profile edits cannot change account activation.
- SR password resets and auth-email listing use authenticated server functions that verify an active admin through RLS before loading the privileged auth client; reset targets must be SR-only and no password is returned or logged.
- AppShell owns role-aware navigation: mobile uses five visible icon destinations with an admin overflow sheet, while desktop exposes all destinations; reserve safe-area space so content remains reachable.
- Business sharing prepares a local PDF/Excel file from the authorized preview, then invokes Web Share from a separate click to preserve user activation; unsupported browsers offer download, never public financial URLs.
- Offline data lives in account-scoped IndexedDB; cached roles only gate local views, never authorize server writes. Financial outbox entries retain their idempotency keys and synchronize in order through post_transaction; conflicts stop the queue without deleting entries, and provisional documents are labeled.
- Outbox payloads are immutable per request key; successful RPC acknowledgement persists before snapshot read-back, exact-entry matching controls removal, and local revisions prevent slow refreshes from overwriting newer synchronized accounts.
- Offline authentication/security changes stay online-only; PWA app-shell service workers are generated by vite-plugin-pwa and registered only through the guarded pwa wrapper, never in development or Lovable previews.
- Offline catalog changes synchronize atomically through admin-authorized post_catalog with per-user request idempotency; navigation caching never stores authenticated HTML and falls back to the prerendered anonymous TanStack SPA shell.
- Preserve trailing slashes in router URLs so the prerender request for the anonymous SPA shell renders directly without a redirect, which production prerender does not follow.
- CompanyLogo centralizes the company image for login, app headers and paginated business papers; pages, exports and PWA precaching share the absolute public asset URL from company-brand so external hosts never request Lovable's asset gateway locally; favicon and installed-app icons derive from the same supplied asset.
- Vercel deploys build with NITRO_PRESET=vercel (vercel.json); vite.config.ts switches the PWA output dir to .vercel/output/static outside Lovable builds so the offline shell and service worker land in the published static folder.
- Settings device backups contain only account-scoped saved snapshots and pending evidence, never credentials or cached authority; online-verified restore accepts the same project/account only, never replays imported outbox entries, and reset/restore block pending work transactionally. Full Cloud backup/restore stays in the managed editor; no full-dump or online financial erase endpoints.
- Catalog history guards reject deletion of linked stock/history both locally and in PostgreSQL; SR name editing uses active-admin-only set_sr_name, with deactivation instead of account deletion to preserve history.
- User access management is active-admin-only through manage_user_access with serialized updates, expected-state conflict detection, required reasons and append-only access_audit; self/last-active-admin changes and promotion of SRs with transaction history are blocked. Existing set_sr_active delegates to the same audited path, and the UI permission matrix describes enforced role scopes rather than cosmetic permission overrides.
